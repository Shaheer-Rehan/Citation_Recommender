The Core Concept — Why SPECTER2?

A standard text embedding model (e.g. text-embedding-ada-002) maps text to vectors based purely on word co-occurrence patterns from web text. It has no understanding of the academic citation graph — the network of "paper A is important enough that paper B cites it". SPECTER2 was fine-tuned specifically on that signal: for every anchor paper A that cites paper B, the model is trained via triplet loss to pull A and B close together while pushing A away from a random unrelated paper. The result is an embedding space where papers that researchers actually treat as related — regardless of vocabulary — cluster together.

Generic embedding (e.g. ada-002)

"Attention Is All You Need" and a paper about customer attention in retail may score high cosine similarity — same word, different universe. No knowledge of citation structure.

SPECTER2 (citation-aware)

"Attention Is All You Need" clusters tightly with BERT, GPT, and T5 papers — not because of shared vocabulary but because thousands of papers cite them together. Structural academic proximity encoded.

Component Details

Phase 01 · Data

Semantic Scholar API

  • Free API, ~100 req/s with key. Register at semanticscholar.org
  • Fields to fetch: title, abstract, year, citationCount, references, fieldsOfStudy
  • Strategy: bulk search by field (e.g. query=machine+learning&fieldsOfStudy=Computer+Science) then paginate with offset
  • Target ~50k papers with non-empty abstracts in CS/ML/NLP
  • Store references as a list of paper IDs — needed for citation overlap re-ranking
Phase 02 · Core Innovation

SPECTER2 — Citation-Informed Embeddings

SPECTER2 (Allen AI, 2023) is a transformer-based model fine-tuned from SciBERT using a triplet loss over the Semantic Scholar citation graph. For each anchor paper A that cites paper B, B is the positive. A random paper C is the negative. The model minimises dist(A,B) and maximises dist(A,C) — so the learned space encodes "papers researchers consider related" rather than surface lexical overlap.

// Training objective (triplet loss)
L = max(0, dist(anchor, positive) − dist(anchor, negative) + margin)

// Input format SPECTER2 expects
text = f"{'{'}title{'}'}" + tokenizer.sep_token + f"{'{'}abstract{'}'}"

// Load model
model = AutoModel.from_pretrained("allenai/specter2")
  • Output: 768-dimensional float vector per paper. Batch process 32–64 at a time
  • Max 512 tokens — titles + abstracts fit comfortably within this limit
  • L2-normalise all vectors before storing so FAISS inner product = cosine similarity
  • Runtime: ~2–4 hours to embed 50k papers on CPU; ~20 min on GPU
Phase 02 · Indexing

FAISS Vector Index

  • Facebook AI Similarity Search — efficient ANN for dense vectors
  • Use IndexFlatIP (exact inner product) for ≤100k papers — no approximation error
  • After L2-normalisation, inner product equals cosine similarity
  • Query returns top-K paper indices + similarity scores in <5ms on CPU
  • Save: faiss.write_index(index, "papers.index") — loaded once at app startup via @st.cache_resource
  • Pair with a pandas metadata DataFrame indexed by FAISS position
Phase 03 · Retrieval

Two Query Modes

  • Single paper: embed query title+abstract → 768-dim vector → FAISS search
  • Reading catalogue: embed each paper in the user's list → compute mean vector → FAISS search (exclude already-read papers from results)
  • Mean pooling works because in a well-trained embedding space, the centroid of N read papers approximates the user's research interest region
  • Optional: weight catalogue embeddings by recency (exponential decay) or user rating if available
  • For ArXiv mode: fetch abstract via arxiv Python package using paper ID
Phase 04 · Scoring

Hybrid Re-ranking

Pure semantic similarity can surface papers that share vocabulary but sit in different research sub-communities. Citation overlap is a complementary structural signal.

score = α × cosine_sim + (1−α) × citation_overlap

// citation_overlap: Jaccard-like
cite_overlap = |refs(query) ∩ refs(candidate)| / max(|refs(query)|, 1)

// α = 0.7 (tunable hyperparameter)
  • α is a tunable hyperparameter — experiment with 0.5–0.9
  • Optional boosts: recency weight (newer papers), log(citationCount) for authority
  • Applied only to top-50 FAISS candidates — cheap at this scale
Phase 05 · Explainability

Sentence-Level Attribution

For each recommendation, surface which part of the candidate abstract is most relevant to the query — this is the "why" the user sees in the demo.

  • Split query abstract and candidate abstract into sentences using nltk.sent_tokenize
  • Embed sentences with a lightweight model: all-MiniLM-L6-v2 (fast, 384-dim)
  • Find the sentence pair (one from each) with the highest cosine similarity
  • Template: "Relevant because: '[candidate sentence]' relates to your interest in '[query sentence]'"
  • Addresses the job description's explicit emphasis on model explainability
Phase 05 · Interface

Streamlit Demo

  • Tab 1 — Single Paper: text inputs for title + abstract, plus ArXiv ID auto-fetch button
  • Tab 2 — Reading List: paste or upload CSV of paper titles
  • Sidebar filters: year range slider, min citation count, field of study multiselect
  • Result cards: title · year · citation count · similarity score badge · Semantic Scholar link · explanation text
  • FAISS index + metadata loaded once at startup with @st.cache_resource — instant queries at runtime
  • Runs locally: streamlit run app.py — screenshottable for portfolio
Phase 05 · Evaluation

Offline Evaluation

Gives you concrete numbers to quote in interviews and a legitimate benchmark for the README.

  • Method: leave-one-out on citation links. Hold out 500 test papers. For each, query the FAISS index and check if the paper's real citations appear in top-K
  • Baseline comparison: same evaluation on TF-IDF cosine similarity — demonstrates SPECTER2 advantage quantitatively

Key Interview Talking Points

Why did you use SPECTER2 instead of a general embedding model?
General models embed based on lexical patterns from web text. SPECTER2 was fine-tuned with citation links as supervision — if two papers are co-cited, they should be close in the embedding space. This encodes academic proximity that vocabulary alone misses.
Why FAISS and not simple cosine similarity over the full corpus?
Brute-force cosine over 50k vectors is fast enough (<1s), but the two-stage architecture — cheap ANN retrieval then expensive re-ranking on just top-50 — mirrors how production recommenders scale to millions of items.
How does the reading catalogue mode work?
Each paper in the user's history is embedded and the vectors are mean-pooled into a single "taste profile" vector. In a well-trained space, the centroid represents the average research interest region, which FAISS can query directly.
How did you evaluate the recommender without explicit user ratings?
Leave-one-out on citation links. If paper A cites paper B in reality, a good recommender should surface B in top-K when queried with A. This gives Precision@10, Recall@10, NDCG@10, and MRR — compared against a TF-IDF baseline.
